## Теорія

### Клас (class)
Клас у Python — це «чортеж» або «шаблон», який описує спільні властивості та поведінку об'єктів певного типу. Наприклад, клас `Player` визначає, що кожен гравець має ім'я, здоров'я та інвентар. Клас оголошується ключовим словом `class`, а всередині задають атрибути та методи.

### Об'єкт (object / instance)
Об'єкт (або екземпляр класу) — це конкретна реалізація класу, створена за допомогою конструктора. Якщо `Player` — це загальний опис «гравця», то `hero = Player("Oleh")` — це конкретний гравець на ім'я Олег, власний об'єкт із власними значеннями атрибутів.

### Атрибут (attribute)
Атрибут — це змінна, яка належить об'єкту (або класу). Наприклад, `self.health = 100` у конструкторі `Player` означає: кожен екземпляр гравця матиме власне здоров'я. Доступ до атрибутів здійснюють через крапку: `hero.health`.

### Метод (method) та self
Метод — це функція, оголошена всередині класу, яка працює з атрибутами конкретного об'єкта. Перший параметр будь-якого методу (крім static/class) завжди називають `self` — це посилання на поточний об'єкт. Наприклад, `def heal(self, amount): self.health += amount` додає здоров'я саме тому гравцю, для якого викликано метод.

### Flask route (маршрут)
Route у Flask — це прив'язка URL-адреси до Python-функції (обробника). Наприклад, декоратор `@app.route("/game")` каже: «коли користувач відкриє `/game` на сервері, виконай функцію `game_view()`». Результатом функції зазвичай є HTML-сторінка, згенерована через шаблон.

### HTTP метод GET
GET — це основний HTTP-метод для **отримання** даних із сервера. Коли ви вводите адресу в браузері або клікаєте на посилання, браузер відправляє GET-запит. У Flask route з методом GET з'являються сторінки, які можна просто відкрити (напр. головна сторінка, сторінка гри).

### HTTP метод POST
POST — це HTTP-метод для **відправки** даних на сервер (напр. вмісту HTML-форми). Використовується, коли потрібно щось змінити на сервері: створити гру, виконати дію, відправити форму входу. У Flask route позначають `methods=["POST"]`, а дані читають через `request.form`.

### HTML форма (form)
HTML-форма — це елемент сторінки (`<form>`), який дозволяє користувачеві ввести дані та відправити їх на сервер. Атрибут `method="POST"` визначає метод відправки, а `action="/action"` — URL-адресу обробника. Елементи `<input>`, `<button>` з атрибутом `name` передають свої значення на сервер.

### Session (сесія) у Flask
Session у Flask — це механізм для зберігання даних про користувача **між запитами** (наприклад, стан гри). Flask зберігає session у зашифрованому cookie. Для шифрування обов'язковий параметр `SECRET_KEY`. У прикладі ми зберігаємо в session словник `game_state`, а потім відновлюємо з нього об'єкт `Game`.

### Jinja2 template engine
Jinja2 — це вбудований у Flask шаблонізатор, який дозволяє вставляти змінні Python, цикли та умовні оператори прямо в HTML-розмітку. Синтаксис: `{{ змінна }}` для виводу значення, `{% if ... %} ... {% endif %}` для умов, `{% extends "base.html" %}` та `{% block %}` для спадкування шаблонів.

## Практика (9 кроків)

### Крок 1. Створення класу Player
У файлі `game/player.py` створюємо клас `Player`. Додаємо атрибути: `name`, `health`, `score`, `inventory` (список), `current_location`. Додаємо методи: `take_damage(amount)` (зменшує здоров'я, але не нижче 0), `heal(amount)` (лікує, не вище 100), `add_item(item)` (додає в інвентар), `is_dead()` (повертає True, якщо HP ≤ 0).

### Крок 2. Створення даних гри — data.py
У файлі `game/data.py` описуємо статичні дані гри у вигляді словників:
- `LOCATIONS` — словник локацій (village, forest, cave, shop, castle) з назвою, описом та списком дій;
- `ITEMS` — словник предметів (key, potion, sword, map);
- Константи: `WIN_ITEM = "key"`, `FINAL_LOCATION = "castle"`, `HEAL_AMOUNT = 40`, `MONSTER_DAMAGE = 35`, `MONSTER_SCORE_REWARD = 50`, `SHOP_POTION_COST = 10`.

### Крок 3. Створення класу Location
У `game/location.py` створюємо клас `Location`, який «обгортає» словник із `data.py`. Конструктор приймає `location_id` та `data` і зберігає `id`, `name`, `description`, `actions`. Додаємо метод `get_action(action_id)` для пошуку дії, метод `to_dict()` для серіалізації та класовий метод `from_id(location_id)`, який витягує дані зі словника `LOCATIONS`.

### Крок 4. Створення класу Game
У `game/game.py` реалізуємо головний клас `Game`, який поєднує `Player` та `Location`. Конструктор приймає `player_name` і створює `Player`. Додаємо властивості (properties): `current_location`, `is_won`, `is_lost`, `is_finished`. Головні методи:
- `to_dict()` / `from_dict()` — серіалізація/десеріалізація стану гри для session;
- `get_available_actions()` — повертає дії, дозволені зараз (приховує недоступні, наприклад, «Use Potion» якщо potion відсутній; додає «Journey to Castle» у Лісі);
- `do_action(action_id)` — знаходить відповідний приватний метод `_act_*` та викликає його;
- Методи `_act_move_forest`, `_act_cave_explore`, `_act_castle_use_key` та інші, що реалізують логіку дій, перемог та поразок.

### Крок 5. Підключення Flask — app.py
У `app.py` пишемо функцію `create_app()`, яка створює екземпляр Flask. Завантажуємо змінні оточення через `dotenv`, встановлюємо `SECRET_KEY` та налаштування session. Додаємо функції-обробники з декораторами `@app.route(...)`:
- `GET /` → `index()` — рендерить `index.html`;
- `POST /start` → `start()` — читає ім'я з `request.form`, створює `Game`, зберігає в `session["game_state"]`, робить redirect на `/game`;
- `GET /game` → `game_view()`;
- `POST /action` → `action()`;
- `GET /result` → `result()`;
- Допоміжна функція `_restore_game()` — відновлює `Game` з session або повертає `None`.
Внизу файлу: `app = create_app()` та запуск `app.run(...)` якщо файл виконано напряму.

### Крок 6. Створення шаблонів Jinja2
У теку `templates/` кладе чотири файли:
- `base.html` — базовий шаблон: `<head>` із CSS (`url_for('static', filename='style.css')`), заголовок сайту та `{% block content %}{% endblock %}` для вмісту дочірніх шаблонів;
- `index.html` — `{% extends "base.html" %}`: форма з полем `name` та кнопкою `Start Game` (POST на `/start`);
- `game.html` — розширює base: виводить `player.name`, `player.health` (як progress bar), `player.score`, `player.inventory`, поточну локацію (`location.name`, `location.description`), останнє повідомлення `last_message` та список кнопок-форм для кожної дії з `actions`;
- `result.html` — виводить «You WON!» або «You LOST» залежно від `is_won`, фінальне повідомлення, фінальний score та фінальний інвентар.

### Крок 7. Створення HTML форм Start Game і Actions (POST)
- Форма старту (`index.html`): `<form method="POST" action="{{ url_for('start') }}">`, `<input type="text" name="name" placeholder="Your name">`, `<button type="submit">Start Game</button>`.
- Форми дій (`game.html`): для кожної дії з списку `actions` генеруємо окрему форму-рядок:
  ```jinja
  {% for action in actions %}
    <form method="POST" action="{{ url_for('action') }}">
      <input type="hidden" name="action" value="{{ action.id }}">
      <button type="submit">{{ action.label }}</button>
    </form>
  {% endfor %}
  ```
Тобто кожна кнопка — це окрема форма, яка відправляє на `/action` приховане поле `action` з `id` дії.

### Крок 8. Обробка дій у Flask route /action
У `app.py` функція `action()` робить наступне:
1. Відновлює `game = _restore_game()`.
2. Якщо гри немає — редірект на `/`.
3. Читає `action_id = request.form.get("action")`.
4. Викликає `game.do_action(action_id)`.
5. Зберігає оновлений стан: `session["game_state"] = game.to_dict()`.
6. Якщо гра закінчена (`is_finished`) — редірект на `/result`, інакше — назад на `/game`.
Таким чином, будь-яка дія оновлює session і залишає стан гри між HTTP-запитами.

### Крок 9. Запуск гри python app.py і проходження
У терміналі (з активованим `.venv`) запускаємо:
```bash
python app.py
```
Сервер стартує на `http://127.0.0.1:5000`. Проходимо повний цикл: Village → Forest (Search → +10 score, предмет) → Cave (Explore → key +30 score, Fight → sword +50 score -35 HP) → Forest → Village Shop (купити potion за 10 score) → Forest → Castle → Use Castle Key → Win (+100 score). Перевіряємо як працює HP, score, інвентар, умови перемоги та поразки (якщо HP впаде до 0 в бою — побачимо LOST).
